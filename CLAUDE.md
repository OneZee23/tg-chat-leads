# CLAUDE.md

Контекст для ассистентов в репозитории **teach-track-leadgen**.

## Что это

Локальный инструмент сбора лидов для TeachTrack. Читает чаты преподавателей от
личного телеграм-аккаунта (GramJS / MTProto), вылавливает тех, кто рекламирует
свои услуги, складывает уникальным списком в Postgres. Рассылка — руками,
автоматизировать её здесь **нельзя**: это прямой путь в спамблок аккаунта.

Не сервис. На VPS не деплоится, CI нет. Запускается на маке, когда нужен.

## Запуск

```bash
yarn install
yarn db:up                      # postgres в docker, порт 5434
cp .env.example .env            # заполнить TG_*, SCAN_CHATS
yarn session:create             # интерактивно, печатает TG_SESSION
yarn typeorm migration:run
yarn start:dev
```

## Архитектура

- `src/main.ts` → `src/app.module.ts`
- `src/common/config/` — `@UseEnv` + `ConfigFragment` (валидация env на старте),
  как в `teach-track-backend`
- `src/infra/` — database (TypeORM + дедлайны запросов), logger (pino), health
- `src/modules/telegram/` — один MTProto-клиент на приложение, сессия из env
- `src/modules/lead/` — сущность лида, upsert через `INSERT … ON CONFLICT`,
  CSV-выгрузка, статусы
- `src/modules/scanner/` — исторический скан по курсору + live-слушатель,
  эвристика `ad-detector.ts`
- `src/migrations/` — TypeORM, `DB_MIGRATE=true` катает на старте
- `inbox/`, `outbox/` — обмен с ассистентом: выгрузка неотвеченного и ответы
  к отправке. Оба в `.gitignore`, там переписка живых людей.

## Важные решения (не откатывать молча)

- **Дедуп в базе, не в коде.** Уникальный индекс по `tg_user_id`. Исторический
  скан и live-слушатель могут увидеть человека одновременно — read-modify-write
  здесь был бы гонкой.
- **Уникальность по `tg_user_id`, не по `@username`.** Ник меняется, id — нет.
- **Курсор в `tg_scan_state`.** Без него каждый запуск перечитывает историю:
  лишние запросы к Telegram (FloodWait) и задвоенные счётчики сообщений.
- **Стоп-слова обнуляют score целиком.** В чатах преподавателей половина
  сообщений — «ищу репетитора» и вакансии школ. Без этого список — мусор.
- **`floodSleepThreshold` + паузы с джиттером.** Ровный ритм запросов — самый
  заметный признак автоматизации.
- **`HOST=127.0.0.1` по умолчанию.** В базе персональные данные третьих лиц,
  наружу торчать нечему.
- **`.env` и `*.csv` в `.gitignore`.** `TG_SESSION` равнозначна доступу к
  аккаунту.
- **Ответы пишет ассистент вне процесса, а не Claude API внутри.** Обмен
  через `inbox/`/`outbox/`: ключей, бюджета и фолбэка нет, а ответы лучше —
  ассистент читает монорепозиторий и видит, что реально в проде, а не слепок
  продукта в промпте. Дизайн: `docs/superpowers/specs/2026-09-03-ai-reply-loop-design.md`.
- **Курсор неотвеченного — последнее НАШЕ сообщение, а не `contacted_at`.**
  Иначе диалог, где мы ответили хоть раз, невидим навсегда, и тёплый лид с
  вторым вопросом теряется. Шаблонный `yarn autoreply` намеренно остался
  одноходовым: со сдвинутым курсором он повторял бы `AUTO_POSITIVE`.
- **Битый outbox роняет разбор целиком.** Половина отправленной пачки хуже,
  чем ни одной: непонятно, где встали.
